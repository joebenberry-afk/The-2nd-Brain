For the requested ASSCharacter memory-delta lifecycle investigation, a fast bounded read-only capture mechanism was built and validated in-session: importing sztool.runtime.winapi.WindowsProcessReader and sztool.runtime.memory.read_bytes directly (instead of spawning the sztool CLI subprocess per read, which measured about 10 seconds per call due to Python cold-start) achieves sub-millisecond bounded reads against a persistent read-only process handle (average about 0.08ms, max about 3.5ms across 50 calls). This is fast enough to poll a bounded 1-4KB region every 10-50ms across a full 15-20 second Blast lifecycle window. Not yet pointed at a live actor: sztool unreal search-objects Kefla currently returns no instance (no active match). The live ASSCharacter object_ptr is normally only known once a telemetry callback fires (from the Lua diagnostic's object_ptr/this_ptr field) or via a live GObjects name-pattern search once a match is active (exact Blueprint instance naming pattern not yet confirmed). Next step: user starts a fresh match, charges to at least 3 Ki bars, stops, lets state settle, then signals ready BEFORE pressing Blast, so the live instance can be located/locked and high-frequency polling started before the single Blast press.
