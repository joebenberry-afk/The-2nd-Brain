# ERRATA — this production record no longer describes the installed host

Recorded 2026-09-21. Read this before using `DEPLOYMENT-MANIFEST.json`,
`HASHES.txt`, `RUN-IDENTITIES.json` or `PRODUCTION-RECORD.json` in this directory.

## What changed

The OMP package was reinstalled: `@oh-my-pi/pi-coding-agent` is now **18.2.8**
(was the 18.2.6 the files here were sealed against). Every file under the
package's `src/task/` carries the reinstall timestamp, and the two files the
patch added are **gone**:

- `src/task/attempt-settlement.ts` — does not exist
- `src/task/cleanup-barrier.ts` — does not exist
- `src/task/isolation-runner.ts` — no longer imports either module

## Consequence for this record

The sealed `installed_sha256` / `bound_sha256` values here describe bytes that
are no longer on disk. They are **historical**, not current.

The qualified launcher refuses, which is the intended behaviour:

```
second-brain: refusing to start - installed bytes do not match the deployment manifest.
  host file missing: src/task/cleanup-barrier.ts
  host file differs from the sealed bytes: src/task/isolation-runner.ts
  ... 10 more
```

That output is the correct outcome of the identity gate, not a defect to work
around. The patched source-entrypoint route is **unavailable**, not merely
"unqualified": it cannot be started through this record any more.

## Effective mode on the installed host

Detected from the live extension context (not from a version banner), published
to `<brain home>/state/host-capabilities.json`:

| Capability | Source | 18.2.8 |
|---|---|---|
| `settlement_observation` | `ctx.observeAsyncJobLifecycle` | absent |
| `attempt_settlement_observation` | `ctx.observeAttemptSettlement` | absent |
| `lifecycle_observation` | `pi.events.on` | present |
| `cancellation_observation` | `ctx.getAsyncJobSnapshot` | present |
| `cleanup_backed_release` | the two observers above | **false** |
| `mutating_delegation` | derives from `cleanup_backed_release` | **refused** |
| read-only delegation, memory, retrieval, injection, telemetry | — | available |

Mutating delegation is refused with `BRAIN_WORKER_SETTLEMENT_CAPABILITY_UNAVAILABLE`.
The frame-only `native_lifecycle` path cannot prove executor settlement or
cleanup, and admitting mutating work there leaves the writer lease held or
quarantined with no release path — that is what produced the quarantined
attempts this repository still carries. Existing ownership protections are
untouched: **no** quarantined lease is released by this errata or by the
capability change.

## Restoring a capable route

Do not reconstruct this deployment record from the old hashes, and do not
re-verify it against 18.2.6 bytes. A capable host must instead demonstrate the
settlement/cleanup capability above — through an upstream-supported interface,
or through a small, separate bridge kept outside the Brain core (v3 requirement:
an OMP update may require adapter changes, never Second Brain core changes).
Seal a new record from the actual bytes at that point.

Until then, `src/cli.ts` from this package is not a launchable Brain route.
