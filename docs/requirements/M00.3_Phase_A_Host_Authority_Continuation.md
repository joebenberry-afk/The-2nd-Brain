## 3. Integrate host credentials without exposing them to the model

Trace the actual `worker_result` implementation before changing it. Determine whether it is a trusted host callback, model-visible tool result, or a wrapper mixing both.

Keep the admission/callback credential in protected host execution context. A model-visible result may carry a non-secret correlation identifier, but must not carry the credential itself. Resolve authority from the host's bound attempt context, not a task/attempt identifier selected in worker-authored result text.

Use an attempt-scoped, action-limited callback capability. Reuse an existing admission credential only if its custody and permitted actions satisfy those limits; otherwise create a narrower host-only callback capability. Do not make one credential authorize admission, renewal, settlement, operator recovery, trusted-memory promotion, and activation indiscriminately.

Do not expose credentials through prompts, public tool arguments/results, transcripts, report packs, error messages, command-line arguments, agent-readable files, or the environment of agent-controlled subprocesses. Test public serialization and logging with a disposable sentinel credential. A clean sentinel scan is evidence for the examined surfaces, not proof of operating-system isolation.

Require authenticated, subject-bound, action-specific authority before any outcome-changing event affects protected state. Cover `record_worker_event` and all alternate CLI, compatibility, wrapper, and host-callback paths. Distinguish accepted authority-bearing events from untrusted reports that are retained only as proposals or telemetry.

A valid credential must not override the lifecycle transition rules. Reject wrong attempt/generation/action, revoked authority, altered replay, and newer-attempt substitution. Preserve exact idempotent retransmission where appropriate without extending authority or changing an accepted outcome. Define restart and late-settlement behavior explicitly; do not turn credential expiry into permission to release ownership.

The host must derive executor settlement and cleanup evidence from its actual lifecycle observations. Merely attaching a host credential to the model's claim “I am finished” is not authoritative settlement.

## 5. Demonstrate actual authority separation

Document the relevant principals and effective capabilities: parent/driver tools as well as workers, shell/interpreter execution, files and database access, inherited handles, host memory/process access, IPC endpoints, executable/configuration mutation, and approval/credential issuance.

Confining children while leaving the driver an unrestricted route to protected host state is not sufficient for an agent-wide claim. Cover every model-controlled execution route that can reach the authority boundary, or state exactly which claim remains unsupported.

Choose the smallest existing host/operating-system mechanism that can enforce the separation. Keep the trusted observer/issuer and authoritative state outside the writable development checkout. Give agent-controlled execution only the project and scratch access it requires. A second process, hidden function, or shared secret is not by itself evidence that the agent lacks the same authority.

Demonstrate permitted project work alongside denied access to credentials, trusted consumer code/configuration, protected database state, and approval issuance. Also test whether an allowed host endpoint can be induced to attest caller-invented lifecycle facts. Evidence custody and observation correctness are separate requirements.

Use disposable processes, paths, and candidate installations within the existing authorization. Do not silently create permanent OS accounts/services, change machine-wide ACLs, elevate privileges, or change the production deployment. If the selected implementation requires such provisioning, deliver the bounded dependency and keep separation unproved until separately authorized and tested.

A shared secret is not intrinsically the defect. The defect is authority that agent-controlled execution can obtain, exercise outside its scope, or bypass by changing the consumer or protected state. Likewise, switching to signatures does not establish separation when the agent can invoke the signer or change its verifier.

Keep core lifecycle/receipt semantics harness-independent; put Windows/OMP-specific isolation and observation plumbing in the relevant adapter/host boundary.
