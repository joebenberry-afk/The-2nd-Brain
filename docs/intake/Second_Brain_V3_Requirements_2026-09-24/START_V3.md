## Development direction

Start V3 development from the actual activated M00 code/evidence baseline. Keep all development isolated from production and canonical personal memory.

## Execution and evidence discipline

Continue bounded candidate-development packets using the native harness's existing agent/reviewer facilities where authorized. Do not create Brain-owned agents or a new control plane. Do not require the user to repeatedly restate architectural decisions already recorded here.

Do not push, upload private memories, tag a release, change production configuration, migrate the live database or restart a user's live services without the relevant authorization. A fresh gateway restart may remain an explicit deployment action rather than a claim that an in-process plugin already changed.
