# T4.1 report — A2A worker lifecycle and leases

## Delivered

- Added the guarded `WorkerLifecycle` state machine with immutable terminal states.
- Added worker event persistence, lease renewal (including duplicate delivery heartbeats), packet-hash idempotency/conflict protection, orphan rejection, one-shot actionable redelivery, rejected-worker transitions, and lease reaping. Expired working tasks become `FAILED(lease_expired)` and emit `worker_completed` plus `task_failed` ledger events; redelivery returns the persisted bounded packet dispatch fact and emits a model-free worker message exactly once before `UNACKNOWLEDGED` failure. Tasks without a dispatch payload fail `UNACKNOWLEDGED` without claiming redelivery; event timestamps normalize to UTC. Low-level settlement additionally requires approved evidence to bind to a persisted worker result hash, and corrected results reject failed/cancelled statuses.
- Integrated Hermes worker registration before host execution, authenticated terminal preparation/request no-ops with no budget/context/ledger side effects, duplicate terminal ledger suppression, worker results/review settlement, durable approved-review evidence and packet/result identity checks before review persistence, split handoff telemetry (including rejected outcomes), and model-free worker-event handling. Worker task/result/correction wire lists retain raw list shape, and supplied context handoffs are compared against current source content and the prior snapshot before worker use. Handoff errors preserve machine-readable error codes; reviewed evidence is durably bound to the evidence used for settlement. The Hermes plugin forwards explicitly supplied bounded postcondition evidence and never treats session/context references as proof. Authenticated terminal retries are recognized before budget/context gates; normal delegate retries are explicit terminal no-ops, while correction retries reprepare valid context and preserve packet/result identity through review.
- Added `brainctl worker-plane reap [--json]`. Reap is fail-open at the CLI boundary and zero-token worker reaping also runs from the heartbeat CLI pulse and the Prime P4 `session_start`/`turn_start` bridge.
