Eglantine repo on Windows: new source files must be LF or the pre-commit hook rejects the commit as "trailing whitespace" on every line
- The eval kernel prelude write(path, content) writes CRLF. The session write tool keeps an existing file's endings and writes LF only for a path that does not exist yet.
- Fix that works: delete the file with the edit tool (REM), then write it again with the session write tool (from the kernel: await tool.write({...})) and check the bytes for \r.
- Do not bypass with --no-verify; clang-format is at C:/msys64/ucrt64/bin/clang-format.exe (--dry-run --style=file, ColumnLimit 100).
- Also: build needs the MSYS ucrt64 environment and targets yuzu / yuzu-cmd; tools/nx2/lab_ctl.py is POSIX-only, so bounded lab runs are Popen + timeout + kill.
- After a header-only change one lab build reported wrong numbers until every dependent was rebuilt (27% against 41% for the same wait); cross-check a new meter against QueryThreadCycleTime on the final binary before trusting it.
