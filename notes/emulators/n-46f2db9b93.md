Eglantine MinGW/lld Windows build: thread names and symbols are absent, and Event::WaitFor waits in MWAITX on AMD.
- SetCurrentThreadName is a no-op under MinGW (src/common/thread.cpp ~952) and the exe has no symbols, so EDEN_NX2_SAMPLE (matches threads by GetThreadDescription, symbolizes with dbghelp) finds nothing. Workaround used: external SuspendThread/GetThreadContext RIP sampling + objdump -d at the hot offset.
- Common::Event::WaitFor (thread.cpp ~1120) on Windows+AMD (monitorx) waits the whole timeout in MWAITX, never in the kernel: HostTiming (core_timing.cpp:92) and the GPU thread pending wake (gpu_thread.cpp:143) show as ~98% and ~70-90% of a core in Task Manager while idle-waiting. Measured in FE:FW: 96-98% / 68-79% of RIP samples on the mwaitx instruction.
- GPU split (EDEN_NX2_SPLIT default 2) only starts when gpu_accuracy=0 (Low); default is 1 (High), gpu_split.cpp:131-135. FE:FW dialogue: busiest GPU thread 683 ms/s (High) -> 346 front / 355 back (Low), picture unchanged, still 30 fps cap.
- nx2_switches.txt is read by the Qt frontend only, not eden-cli. EDEN_NX2_NO_TRANSLATION_CACHE=1 has no measurable cost in FE:FW.
