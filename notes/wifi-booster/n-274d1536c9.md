Claude Code native update over aria2: `fast claude update` (also `hup claude`) downloads the release into ~/.local/share/claude/versions/<ver> first.
- Why: campus single connection to downloads.claude.ai = 0.10 MB/s (0.8 Mbps). The native updater downloads claude.exe.zst (106 MB) over one stream with a 10-min deadline, so it fails and leaves a 0-byte versions/<ver> placeholder.
- Updater (2.1.302 code, gt()/ze()): it creates the placeholder with flag "wx" and only touches it if it is 0 bytes. A non-empty versions/<ver> is checked against the signed manifest.json checksum; on a match it logs "already installed, updating symlink" and does not download.
- `<downloaded exe> install <channel>` (install.ps1 style, the old hup claude path) does NOT reuse the running binary; it downloads again. Don't go back to that.
- Measured 2026-10-22: 2.1.302 -> 2.1.308; zst in 73 s with 64 connections (11.6 Mbps); 81 s total; sha256 c9796ba2... OK.
- Type-check fast.ts/hup.ts: make a temp dir, `bun add -d @types/bun typescript`, write a tsconfig with files = both, then `bunx tsc`. Known existing error: fast.ts Server generic (TS2314).
