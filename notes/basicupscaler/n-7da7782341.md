BUF (NET-38) Task 5 design must address the three-fold decode: with 3 LOGO folds each game's data sits in 2 of the 3 per-fold training sums, so any per-fold sum or mean over training games recorded in full (e.g. round-0 fold fits' inner gains, which prereg §8 shows in full) decodes per-game values as total/2 - fold's value. For K0 this leaked K0-in via weighted SSE, so buf.py now drops every fit's SSE from registry lines on a continue (BUF-4 review 2). For round 0 it yields per-game in-sample gains, which §3's reveal rule does not name as hidden: a prereg decision, give it a line in the Task 5 design.
