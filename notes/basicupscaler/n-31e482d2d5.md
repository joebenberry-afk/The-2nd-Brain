30 Sep 2026: I benchmarked BUNet training (42 ms per step, 2.3x the plan) before checking whether a Windows build of Triton existed (it does: `triton-windows` on PyPI). The owner: "if there was a windows version you could have let me know before benchmarking."

**Why:** the owner wants the fastest quality-neutral iteration loop ("the faster we can improve the model and find faults"); a missed tool costs weeks of GPU time.
**How to apply:** before a benchmark, a long run or a toolchain choice, spend a few minutes checking for existing faster options (community Windows ports, built-in PyTorch features like CUDA graphs, fused kernels) and tell the owner up front. Speedups are welcome only if quality is unchanged (verify equivalence against the exact ports/emulator). Related: [[fast-reliable-efficient]], [[best-not-basic]].

The same applies to tools we already have. On 1 Oct I gated the BUF-T oracle test on building Godot phase 2, but AMD Capsaicin (IDEAS PRB-12) was already built on this laptop and gives true MVs plus FSR 3.1.5. Research report 21 caught it. Before naming a test's prerequisite, grep IDEAS PRB-/CAP- rows for something already built.
