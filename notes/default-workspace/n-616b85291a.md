DSH desktop plugins are `link:` deps in ~/.dsh/profiles/desktop/package.json — moving a plugin folder breaks app boot, not just the widget.
Boot resolves each dsh.profile.bundles name via createRequire from the profile; a dead link throws `cannot resolve profile bundle "@local/..." from the dsh installation or <profileDir>` (dsh-app-boot/lib/index.js ~L831) before the server starts. Fixes: keep folders put, or repoint the link: specifier and re-run install.
Re-install command (bundled runtime, no global pnpm needed):
node "C:\Users\assas\AppData\Local\Programs\DeepSeek Harness\resources\runtime\primary-runtime\dependencies\node\bin\node.exe" "...\runtime\primary-runtime\dependencies\pnpm\bin\pnpm.mjs" install --ignore-scripts --reporter=append-only  (workdir = the profile dir)
Live profile for the desktop app is the one in its process cmdline: ... dsh-desktop-host\lib\index.js <app.asar dsh> C:\Users\assas\.dsh\profiles\desktop.
Neutral home for user plugins: ~/.dsh/plugins (never the Programs install dir — app updates replace it, and app.asar is a packed archive).
