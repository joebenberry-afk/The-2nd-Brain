DSH subscription auth (Claude Max / ChatGPT Plus) has no UI: write pi-ai OAuth grants into the credential store yourself
The desktop harness has no stock sign-in button for pi-ai subscription providers. What works: run @earendil-works/pi-ai's own login flows, then store the credential verbatim as a harness record in ~/.dsh/.credentials.yaml:
  *** {kind: grant, payload: {type: oauth, refresh, access, expires}}
  llm-pi-ai/openai-codex: {kind: grant, payload: {type: oauth, access, refresh, expires, accountId}}
credentials-local watches the file, so routes authenticate on the next request with no restart. Routes must already be declared in the profile's llm-pi-ai providers (the desktop patch here declares anthropic and openai-codex).
How to run the flows: extract @earendil-works/pi-ai out of app.asar with a readFileSync walk (fs.cpSync fails on asar paths), then plain node calls dist/auth/oauth/anthropic.js (login(interaction), choose copy_code) and openai-codex.js (choose browser: it auto-captures the redirect on localhost:1455). Electron-as-node works for the import but silently exits when started as a background job — use plain node for long-running flows.
Verified end-to-end: workflow agent() with provider/model override returned answers from anthropic/claude-sonnet-5-5 and openai-codex/gpt-6.1-sol.
