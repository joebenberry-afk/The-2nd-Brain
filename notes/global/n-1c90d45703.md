eval `commit` namespace silently leaves out a file whose working copy is CRLF when the repo has core.autocrlf=true
The commit succeeds and returns a `paths` list without that file. Check `git ls-files --eol <path>` (w/crlf = will be skipped) and compare the returned `paths` with what you meant to commit. Fix: rewrite the working copy with LF by a binary write (the prelude `write()` re-emits CRLF on Windows), then commit again.
