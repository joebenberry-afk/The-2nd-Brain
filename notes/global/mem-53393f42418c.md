T1 production live canary: per-poll reset bug found and fixed, player trial PASSES

During the T1 production live canary (Phase 7), blast_committed never fired despite confirmed real current_blast_id transitions, across both a Ctrl+F8 reload and a full game restart. Root cause: a fourth BLAST_COMMITMENT_TRACKER.reset() call site, originally believed to be a one-time match-becomes-active transition handler and added for defense-in-depth, was actually the unconditional top of the poll-while-active code path in main.lua, re-executed on every poll tick (tens of times per second) for the entire active-match duration. It wiped the SIDE+TEAM_SLOT tracker state continuously, so no observation could ever see a prior baseline.
